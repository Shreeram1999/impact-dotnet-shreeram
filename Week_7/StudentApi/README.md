# Student API (Week 7) - three interchangeable data layers

The Week 6 API (Student/Teacher CRUD, the grade Strategy/Factory, and the
PBKDF2 + JWT login), now on real SQL Server persistence. The same
repository interfaces are implemented three ways, and one setting picks
which one runs:

| `DataLayer:Provider` | Folder | Database |
|---|---|---|
| `AdoNet` | `Data/AdoNet` | `StudentPortal_Week7` (hand-written scripts in `../Database`) |
| `EfCodeFirst` (default) | `Data/EfCodeFirst` | `StudentPortal_Week7_EfCodeFirst` (generated by migrations) |
| `EfDbFirst` | `Data/EfDbFirst` | `StudentPortal_Week7` (scaffolded from it) |
| `InMemory` | `Data/InMemoryRepository.cs` | none (Week 5/6 behaviour; used by the HTTP tests) |

Controllers, Services, DTOs and auth are identical whichever layer runs.
See `../DATA-COMPARISON.md` for which approach fits which job.

## Setup (LocalDB, from the `Week_7` folder)

```
# 1. Hand-built database for ADO.NET + DB First (Task 7.1/7.4)
sqlcmd -S "(localdb)\MSSQLLocalDB" -i Database/01_CreateDatabase.sql
sqlcmd -S "(localdb)\MSSQLLocalDB" -d StudentPortal_Week7 -i Database/02_Schema.sql -i Database/03_StoredProcedures.sql -i Database/04_SeedData.sql

# 2. Code First database from the migrations (Task 7.7/7.8)
dotnet tool restore
dotnet ef database update --project StudentApi --context AppDbContext
```

Connection strings live in `appsettings.json` under `ConnectionStrings`
(override them with `ConnectionStrings__StudentPortalSql` /
`ConnectionStrings__StudentPortalEfCodeFirst`); nothing is hard-coded.

## Run on any layer (Task 7.11)

```
dotnet run --project StudentApi -- --DataLayer:Provider=AdoNet
dotnet run --project StudentApi -- --DataLayer:Provider=EfCodeFirst
dotnet run --project StudentApi -- --DataLayer:Provider=EfDbFirst
powershell -ExecutionPolicy Bypass -File smoke-tests.ps1   # same 25 checks against each
```

Verified: `ALL CHECKS PASSED` on all three providers.

## Day by day

- **7.1** - `../Database/ER-DIAGRAM.md` (3NF), `02_Schema.sql`, connection string via `IConfiguration` (`SqlConnectionFactory`).
- **7.2-7.4** - `AdoNetStudentRepository`: `SqlCommand` + `SqlDataReader` reads, parameterized writes,
  `usp_GetStudentById` / `usp_InsertStudent` via `CommandType.StoredProcedure`, plus a
  `SqlDataAdapter`/`DataSet` example (`GetAllAsDataTable`). The injection string
  `'; DROP TABLE Students;--` is stored as literal text (test + smoke check).
- **7.5** - `AdoNetUserStore : IUserStore`. Login verifies against `dbo.Users`, and nothing else in the auth code changed.
- **7.6-7.8** - `AppDbContext` (Fluent API: unique Email/RollNumber/Username indexes, check
  constraints, optional one-to-one `User` links, `HasData` seed); migrations `Initial` then
  `AddEnrolledOn`, both in `Data/EfCodeFirst/Migrations`.
- **7.9-7.10** - scaffolded with:
  ```
  dotnet ef dbcontext scaffold "Server=(localdb)\MSSQLLocalDB;Database=StudentPortal_Week7;Trusted_Connection=True;TrustServerCertificate=True" Microsoft.EntityFrameworkCore.SqlServer --project StudentApi --output-dir Data/EfDbFirst/Entities --context-dir Data/EfDbFirst --context StudentPortalDbFirstContext --namespace StudentApi.Data.EfDbFirst.Entities --context-namespace StudentApi.Data.EfDbFirst --no-onconfiguring --table dbo.Users --table dbo.Students --table dbo.Teachers
  ```
  Re-run it after a schema change, and never hand-edit `Entities/`. `DbFirstRepositories.cs` maps scaffolded rows to domain models.
- **7.11** - `Data/DataLayerRegistration.cs`.

Other Week 7 changes: duplicate student/teacher **emails** are now a 409 from
the Services (the database has unique indexes, so letting them through would
be a 500). `StringLength` on the DTOs matches the column lengths, so an
over-long value is a 400. `StudentReadDto` now includes `enrolledOn`.

## Tests

`StudentApi.Tests` has 149 tests, all passing (none skipped on a machine with
LocalDB), with 98.7% line coverage. Generated migrations are excluded via
`../coverlet.runsettings`.

- Services against a **mocked** `IRepository<>`: Week 5/6 tests plus the new email-conflict rules.
- EF Code First against **SQLite in-memory**: CRUD round trips checked through a second
  context, the unique Email index and Age check constraint enforced, seeded login hash verifies.
- EF DB First repositories against EF **InMemory**: every field mapped both ways.
- ADO.NET against a **throwaway SQL Server database** built from the real scripts: injection
  literal, stored procedures, null `EnrolledOn`, unique constraint, `DataTable`, user store.
  Skipped (not passed) if no SQL Server is reachable; set `STUDENTPORTAL_TEST_SQL` to use another server.
- `DataLayerRegistrationTests`: each provider value resolves the right three implementations.
